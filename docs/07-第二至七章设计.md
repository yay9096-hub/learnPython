## 先说一个来自真实使用的信号 ⚠️

**她第一天就做完了 4 天的内容。**

这不是「她太厉害」这么简单，它同时说明两件事：

| 说明了什么 | 后面怎么应对 |
|---|---|
| 第一章的密度对她偏低 | 第二章起每天的项目更大，任务项从 6 项提到 7–9 项 |
| 她愿意连续投入 2 小时以上 | 每天加一个**可选的「挑战关」**，做完主线还想玩就有得玩 |
| 但连做 4 天 = 知识点没有过夜巩固 | 每天的练习题里**混入前几天的知识点**（间隔重复） |

### 三条新增机制

**1. 挑战关（每天可选）**
主线任务通过后解锁，不计入完成条件，纯粹给「还想再玩会儿」的人。
通常是「把今天的项目再加一个功能」，比如猜数字加上难度选择。

**2. 回响练习（间隔重复）**
每天 5 道练习里，固定有 **1–2 道来自 3~7 天前**的知识点。
学过的东西如果一周不碰就会忘，这是最便宜的对抗方式。
在 `exercises.json` 里用 `"echo": 4`（表示回响 Day 4）标记。

**3. 连做提醒（温和，不阻拦）**
一天内完成第 3 天的内容时，派森酱会说一句：

> 「今天已经是第 3 关啦，你也太猛了 (๑•̀ㅂ•́)ｼ✧
>  不过明天再来的话，今天学的会记得更牢哦 —— 当然你想继续我也拦不住！」

**绝不禁止**。她想冲就让她冲，只是提醒一句。

## 要先做的三件工程

这三件不做，对应的章节就立不住。按需要的时间排序：

### 1. 文件持久化（第五章之前，D45 前）✅ 已实现

Pyodide 的文件系统默认是内存 MEMFS，刷新即失。
方案：挂载 **IDBFS**（浏览器 IndexedDB），学生代码写的文件真正存在浏览器里。

```js
py.FS.mkdir("/home/pyodide/我的文件")
py.FS.mount(py.FS.filesystems.IDBFS, {}, "/home/pyodide/我的文件")
await new Promise(r => py.FS.syncfs(true, r))   // 启动时载入
// 每次运行结束后 syncfs(false) 写回
```

还需要一个**文件浏览器面板**（右栏加一个 📁 标签），让她能看到自己写出来的文件 ——
不然「文件」这个概念对她就是黑箱。

### 2. matplotlib 打包（第七章之前，D64 前）✅ 已实现

⚠️ **实现时发现原方案行不通**：npm 的 pyodide 包**不含 wheel 文件**，
Pyodide 默认运行时去 CDN 现取 —— 那样一断网第七章就废了。

改成 `scripts/fetch-wheels.mjs`：从 `pyodide-lock.json` **递归解析依赖**，
构建时从 CDN 下载到 `public/pyodide/`，接进了 `npm run pyodide`。
实测 13 个包共 **12.3 MB**（比预估的 30MB 小得多）。

运行时按需加载：只有代码里出现 `matplotlib` / `numpy` 时才 `loadPackage`，
而且只载一次 —— 不画图的日子启动速度不受影响。

### 3. 挑战关 + 回响练习 ✅ 已实现

- `meta.json` 的 `challenge` 字段（标题 + 描述），主线全过后解锁
- `exercises.json` 的 `"echo": <天数>`，前端显示成「🔁 回响 · Day N」标签
- 一天连做 3 关以上时，通关弹窗里出现温和提醒（后端 `done_today` 字段）
