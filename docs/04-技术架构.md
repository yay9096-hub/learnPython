# 04 · 技术架构

## 一、最关键的选择：Python 在哪里执行？

| 方案 | 优点 | 缺点 |
|---|---|---|
| **Pyodide（浏览器 WASM）** | 零后端沙箱风险、断网可用、部署极简、支持 numpy/pandas/matplotlib | 首次加载约 10MB（本地部署无所谓）、`input()` 需特殊处理、少数库不支持 |
| **后端 Docker 每次起容器** | 真 CPython、`input()` 天然可用、能装任意包 | 要做沙箱、超时、内存限制、并发控制；家用单人属于过度设计 |

### ✅ 推荐：Pyodide 为主

安全性由**浏览器沙箱天然保证**——她写 `while True:` 死循环，最多卡掉一个 Web Worker
（前端加个"停止"按钮 terminate 掉重建即可），不用担心把机器搞挂。

后端只做进度存储和报表，不碰代码执行，架构大幅简化。

## 二、Pyodide 的两个已知坑（提前规划）

### 坑 1：`input()` 默认不工作

而"猜数字"这类交互项目**必须**要它。两个解法：

- **正式方案**：在 Web Worker 里用 `SharedArrayBuffer` + `Atomics.wait` 实现真正阻塞式 `input()`。
  需要给本地服务加两个响应头（nginx 两行配置的事）：
  ```
  Cross-Origin-Opener-Policy: same-origin
  Cross-Origin-Embedder-Policy: require-corp
  ```
- **省事的退路**：用 JS `prompt()` 弹窗覆盖 `builtins.input`。体验差一点，但十分钟能搞定，MVP 够用。

### 坑 2：`turtle` 没有原生实现

需要自己写一个映射到 Canvas 的简版 shim，约 200 行，
只支持 `forward` / `backward` / `left` / `right` / `penup` / `pendown` / `color` / `goto` 这几个常用的就够。

> `matplotlib` 在 Pyodide 里是**开箱可用**的，输出 PNG 到 canvas 即可，无需额外工作。

## 三、技术栈

```
前端  Vite + React + Tailwind CSS
      ├─ CodeMirror 6         ← 编辑器。比 Monaco 轻，中文和主题好定制，
      │                          小白不需要 Monaco 那套复杂智能提示
      ├─ Pyodide (Web Worker) ← Python 运行时，跑在 worker 里不卡界面
      └─ markdown-it          ← 渲染 lesson.md，自定义 runnable 代码块

后端  FastAPI + SQLite        ← 很薄。只管进度、判题结果、作品、家长报表

内容  Markdown 文件目录        ← 挂 volume，改完刷新即可，不用重新构建
```

### 后端到底要不要？

纯前端 + `localStorage` 也能跑，但：
- 清缓存 = 进度全丢（对一个坚持了 40 天的孩子是毁灭性打击）
- 没法做家长视图
- 作品陈列馆的数据没地方放

一个几百行的 FastAPI + 一个 SQLite 文件，值这个成本。**备份就是复制一个文件。**

## 四、判题机制

判题跑在**前端**（Pyodide 里执行 `tests.py`），结果上报后端记录。三种维度混用：

| 维度 | 说明 | 用在哪 |
|---|---|---|
| **stdout 比对** | **宽松匹配**：忽略首尾空白、忽略多余空格、可配置忽略大小写 | 前期没学函数时 |
| **函数返回值断言** | 调用她写的函数，断言返回值 | 学完函数之后（D35+） |
| **AST 结构检查** | 比如"这题必须用 `for` 循环"，防止硬编码答案糊弄过去 | 需要练特定语法时 |

> ⚠️ **绝不能因为多一个空格判她错。** 这是最容易毁掉体验的地方。
> 失败信息必须具体："你的程序猜对之后没有停下来"，而不是"测试 3 失败"。

## 六、docker compose

```yaml
services:
  web:
    # nginx：托管前端静态文件 + 反代 /api
    # 必须带 COOP/COEP 响应头（给 SharedArrayBuffer 用）
    ports: ["8080:80"]

  api:
    # FastAPI
    volumes:
      - ./content:/app/content:ro   # 内容目录，只读挂载
      - ./data:/app/data            # SQLite 持久化
```

启动：

```bash
docker compose up -d
```

浏览器打开 `http://localhost:8080` 即可。

`content/` 和 `data/` 都是宿主机上的普通文件夹，**备份就是复制文件夹**。

> 也可以做成**单容器**（FastAPI 直接托管前端静态文件），更省事。
> 但 compose 两容器的结构以后想扩展（比如换成后端真实执行 Python）更方便。
