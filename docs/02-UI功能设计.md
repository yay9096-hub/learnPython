# 02 · UI 与功能设计

## 一、每日页面（主战场）

```

│ Day 12 · 猜数字游戏      ▓▓▓▓▓▓░░░░ 12/70   🔥 连续 9 天      │
│ 今天你会做出一个能和你对话的游戏                                │
├───────────────┬──────────────────────────┬────────────────────┤
│ 今日剧情       │  editor.py                │  ▶ 输出            │

│               │  1  import random         │  猜一个数字:        │
│ 📌 知识卡 1    │  2  answer = random...    │  > 50              │
│  while 循环    │  3  # TODO: 写一个循环     │  太大了！           │
│  [▶ 试一下]    │  4                        │                    │
│               │                           │  ✅ 任务清单        │
```

三栏布局：**左讲解 / 中编辑器 / 右输出+任务**。这是 Codecademy 等验证过的事实标准。

## 二、关键交互细节

### 知识卡里的 `[▶ 试一下]`
每个知识点旁边挂一段 3 行的可运行迷你代码，点一下当场出结果，还能随手改。
这是 Khan Academy 最有效的设计——**读到的每一句都能立刻验证**，而不是读完一大段再去写。

### 分级提示（三级台阶）
提示不是一个按钮直接给答案，而是逐级放开：

1. **思路引导** —— "想想循环什么时候该停？"
2. **伪代码** —— 用中文描述每一步该做什么
3. **关键代码片段** —— 只给最难的那两行

第四级"查看参考答案"要**二次确认**，并且看了之后仍然要求她自己敲一遍才算通过。

### 任务清单实时打勾
点「检查任务」跑判题，通过的项打勾变绿。没过的项要给出**具体哪里不对**，
而不是笼统的"失败"。例如："你的程序猜对之后没有停下来，还在继续问。"

### 报错翻译面板
出错时输出区不只显示英文 Traceback，下面折叠一段中文人话解释 + 指向对应知识点的链接。
详见 [01-产品设计](01-产品设计.md#2-报错信息是零基础最大的劝退点--做中文报错翻译器)。

### 代码自动保存
她关掉浏览器明天回来，代码还在原处。任何时候都不该丢失她写的东西。

### 答案对比（做完后解锁）
完成任务后，可以看「我的写法 vs 参考写法」的并排 diff，
并附一句说明参考写法好在哪（或者"你的写法其实更好"）。

## 三、全局功能

| 功能 | 说明 | 优先级 |
|---|---|---|
| **首页日历热力图** | 70 个格子，做完的变绿，点开进入当天。视觉上"我已经走了这么远" | P0 |
| **作品陈列馆** | 每完成一个项目生成一张作品卡（项目名 + 输出片段 + 完成日期），可一键"分享给爸爸看" | P0 |
| **中文报错翻译** | 最常见 30 条 Traceback 的中文映射 + 常见原因 + 知识点跳转 | P0 |
| **速查手册** | 随时能查语法，但**只包含她已经学过的内容**——避免看到没学的被吓到 | P1 |
| **错题本 / 卡壳记录** | 哪天提示用得多、报错次数多，自动收进复习清单，第 7 天复习日用 | P1 |
| **变量可视化** | 单步执行时高亮当前行 + 显示变量表（Python Tutor 式） | P1 |
| **家长视图** | 看她这周做了几天、卡在哪个知识点。做得非常轻 | P2 |
| **深色 / 浅色主题** | 等宽字体够大，晚上写代码不刺眼 | P2 |
| **移动端只读** | 手机上可以回顾讲解和作品，但不写代码 | P2 |

> ⚠️ 家长视图如果做，**要让她知道有这个页面**。偷偷监视会毁掉信任，
> 得不偿失。理想形态是"每周一起看一次的周报"，而不是监控台。

## 四、有意不做的功能

| 不做 | 原因 |
|---|---|
| ❌ 排行榜、和别人比较 | 家里就一个学习者，比无可比；容易变成压力源 |
| ❌ 倒计时 / 限时答题 | 制造焦虑，和"每天轻松半小时"的定位冲突 |
| ❌ 断签清零 | 断一天不该有惩罚。只显示"最长连续 15 天"这种正向数字 |
| ❌ 移动端写代码 | 手机上敲代码体验极差，会毁掉对编程的第一印象 |
| ❌ 严格的答案字符串匹配 | 多一个空格就判错会非常挫败，判题必须宽松（见 [04-技术架构](04-技术架构.md)） |
